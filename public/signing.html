Code Signing Policy

How the Wren Windows installer is built, who approves it, and how you can check that the copy you downloaded is the one we published.

Status. Wren's installer is not yet code-signed. Windows SmartScreen will warn on first run — see the download page. This page describes the signing process being put in place; it will be updated the moment signing goes live.

How Wren is built

Every released installer is produced by an automated, public build — never on a developer's machine, never by hand:

  • Source lives at github.com/buildwithbaker/wren under the MIT licence.
  • Pushing a version tag (v1.2.4) triggers the Release workflow, which builds the Windows NSIS installer on a clean GitHub-hosted runner straight from that tag's source.
  • The workflow uploads the installer to the matching GitHub Release. That Release asset is the only artifact we publish, and the download button points at it.
  • The build definition is public, so anyone can read exactly how the binary was made and reproduce it from the same tag.

Who approves a release

Wren is a single-maintainer project. Adam Baker (@buildwithbaker) holds all three roles:

  • Author — writes and commits source changes.
  • Reviewer — reviews every change from any outside contributor before it can merge. main is a protected branch: changes land only through a pull request with continuous integration green.
  • Approver — decides which tagged build is released and, once signing is live, authorises each signing request individually.

Multi-factor authentication is enabled on the GitHub account and on the code signing service account.

What gets signed

Only the Windows installer produced by the automated build above, from Wren's own source. We do not sign locally-built binaries, third-party software, or artifacts from any other project. Signed binaries carry consistent product name, publisher and version metadata, single-sourced from package.json and verified at build time.

Verifying a download

  1. Download only from the Wren download page or directly from GitHub Releases. We publish the installer nowhere else.
  2. Check the file name matches the release, e.g. Wren_1.2.4_x64-setup.exe.
  3. Once signing is live, right-click the installer → Properties → Digital Signatures and confirm the publisher.

Privacy

Code signing does not change what Wren does with your notes: they stay in the folder you choose on your own computer. No note content is transmitted to the signing service — only the compiled installer is submitted for signing. See the privacy policy.

Reporting a problem

If you find an installer claiming to be Wren that did not come from the sources above, or you suspect a signature has been misused, please open a security advisory or see SECURITY.md.
